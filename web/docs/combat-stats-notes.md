# Weapon and combat calculations

`src/combat-stats.ts` separates original calculations from entity mutation, input, graphics, and scheduling. It reads the complete generated `Item`, including modifications, and numeric trait IDs. The focused tests verify source-derived arithmetic and integration contracts. A separate accepted 22-snapshot original `shoot()` fixture now verifies the integrated Sheriff's tested shot paths; it does not establish runtime parity for every other class or projectile.

The module covers weapon eligibility, shells, accuracy divisor, distance penalty, recoil/recovery, base shot timer, base damage, hitscan bonuses and critical rolls, per-target air/armor multipliers, boss guarding, leech, disarm, cripple, knockback, reload progression, automatic reload start, rampage, living weapon evolution, and projectile dispatch/area dimensions. Unknown hero traits 900/901 produce `null` AI aim/work values. Manual Sheriff combat does not need these hidden values. AI semi-automatic cooldown jitter remains a caller responsibility: add `int(U * (shootRate / 1.5 / workRate))` to `shootTimer`.

Primary source anchors in `src/shootem_fla/MainTimeline.as`: `procHit` 1431; `cancelReload` 2716; `explode` 3094; `reload` 4618; `refreshPlayer` 4670; `explode_puls` 6210; `calcLivingWeaponExp` 6758; `rampage` 7336; `reloading` 7378; `shoot` 7839; recovery and distance penalty 8464; trait definitions 9432–9643; `damageCastle` 10911; `rampageOn` 12351; `throwGrenade` 13409. Enemy arithmetic/status ordering is `.build/export/scripts/enemy.as:550` (`damage`); living weapon evolution begins at 739.

## Calling contracts

- `weaponStats(item, traits, context)` returns `canFire`, `shells`, `accuracyDiv`, `rangeFix`, `recoil`, `recovery`, `shootTimer`, `shootRate`, `intervalFrames`, `reloadTime`, `consumesAmmo`, and nullable `aimTime`/`workRate`. `intervalFrames` is the baseline 30 Hz cooldown representation, before optional AI jitter or chain/bow state. It does not mandate a renderer rate.
- Call `shotSpread` before adding recoil. `recoverAccuracy` represents one original 20 Hz recovery callback. For bows, apply the returned full recoil only when starting the draw, including tight mode; release does not add recoil again.
- `shotDamage` truncates at each original assignment, including rampage. Specials dispatch before `hitscanShotModifiers`. Pass ammo after consumption and recoil after the shot into `hitscanShotModifiers`; it reports burst/recoil changes without mutating input.
- Actual `shoot()` consumes two random draws for every vector geometry hit, including dead enemies: SENSE first, ONE_HIT_KILL second. Pass them to `hitscanHit`. SENSE is divided by shell count; a live weak point overrides the random critical type. ONE_HIT_KILL changes the damage variable shared by subsequent targets and pellets. Preserve its returned `damage` and `specialHitType` across the shot.
- Projectile `procHit()` uses one SENSE roll without shell dilution and no ONE_HIT_KILL roll. Use `criticalType(..., shells=1)` for that boundary. The accepted older combat oracle exercises `procHit`, not a complete shotgun `shoot` call.
- `weaponHitDamage` returns final damage and `beforeGuard`. Leech uses `beforeGuard`, because the source heals before boss guarding reduces damage. `weaponHitEffects` applies leech/disarm/cripple/knockback to a returned target copy. Its optional rolls become required only when the source actually reaches their random calls. `procHit` sets Sheriff knockback before `enemy.damage`; hitscan does not. With zero knock resistance, preserve the incoming knockback rather than inventing another adjustment.
- `advanceReload` represents one original reload callback. `restarted` means a per-shell continuation calls original `reload` again. `completion='manual'` corresponds to `cancelReload`; `'magazine'` corresponds to `sound_reloaded1`. Automatic reload permits firing while the timer runs and starts when cooldown is at most `-3 * shootRate`; its level is not an extra speed multiplier.
- `livingWeaponKill` returns a copy. At the kill threshold it expands capacity up to six, invokes the existing item enchantment generator only if a slot remains, then resets the kill counter to `int(25 * 2^modMax)`. Pass the real combat random source and engineer/medal context. This can refill ammo because original `enchant` does so.
- `weaponPresentation(id)` maps original `getWeaponInfo` to `{sound, shootFrame, idleFrame, endFrame}`. Sound names use the extracted manifest key without the `sound_` prefix. Unlisted IDs use original gun1 / 10 / 24 / 10 fallback; original frames and weapon-specific end poses are retained.

## Equipment input boundary

`KeyDown` (13222) handles keys 1–5; slot 6 has no battle hotkey. Empty slots beep. Occupied consumables call `useItem` (3697) without changing the selected slot or canceling its reload. Every other occupied item can be selected, even if it is not a gun or its skill requirement is unmet; `shoot` checks firing eligibility later. Selecting a slot, including the current slot, clears the outgoing item's reload time and calls `refreshPlayer`. Selection preserves shared shot cooldown, recoil and shooting intent, but resets burst/chain state and the Militia grenade count through `refreshPlayer` (4669, 6747). Inactive items receive no reload ticks.

Space checks partial ammo, no automatic reload and `shootTimer <= 0` before calling `reload`. Mouse-down (12027) cancels manual per-shell reload and returns; it queues fire during magazine reload. Automatic reload is not canceled and allows shooting while its timer advances. Mouse-up (3193) clears burst and shooting; bows additionally release their drawn projectile. A semi-automatic shot clears shooting, while automatic shooting remains active across frames. Empty trigger clears it before starting reload, so a physically held button does not restart firing afterward without another press.

The frame callback (2475) subtracts the selected item's `shootRate`, then attempts an already queued shot. Timer callback (8314) starts automatic reload at `shootTimer <= -3 * shootRate`, then immediately processes its first reload step in the same callback. These are observed callback rules, not a requirement that the browser renderer run at 30 Hz. Original `itemTimer` removes itself only after its counter becomes negative, so a grenade timer initialized to 100 blocks 101 frame callbacks. Its own handler has no pause guard; reproducing that pause defect is not implied by the equipment fixture.

Weapon experience has five buckets in the source order `[Small Gun103, Big Gun106, Rifle104, Shotgun105, other]` (`wexpList`, 9663). `refreshPlayer` chooses the bucket from the selected slot's raw `reqTrait`, without a gun-type or occupancy guard. Inherited metadata on a non-gun or subsequently exhausted consumable therefore still matters. `enemy.damage` (enemy.as733) credits that current selection on every kill, including grenade kills with weapon index −1; it does not use the weapon held when the grenade was thrown. `wexpUp` (6959) processes only the first four buckets after completion XP/level-up: strictly more than `skillLevel * 12 + 20` gives one skill level and clears that bucket, even if it contained enough for several levels. The other bucket is retained. It can learn a previously absent firearm skill; these learned IDs must remain saveable without being added to Sheriff's random choice list. All four source firearm skill definitions have maximum999 (9480–9492). Existing original shoot/procHit fixtures still expose only the selected Shotgun count; their adapters project bucket3 without changing expected data.

## Behaviors the combat loop must still implement

All ordinary generated guns use item fields; ID 16 additionally spins up before firing. IDs 24/25 draw on press and release their arrows on mouse-up. Special projectiles are 21 grenade, 22 rocket, 23/26 bolt, 24/25 arrow, 27 gravity, and 40 flame. These must not be presented as hitscan weapons.

Projectile base speeds are 12 for grenade launcher, 20 for bolts, and 10 for the others. The original throw functions further adjust speed from trajectory; arrows aimed above y=150 receive 1.5x speed and +6 target y, bolts +4 target y, gravity quarter speed, flame 0.75x speed. Wind Bow emits three arrows with start x offsets +5/0/−5 and target x offsets +20/0/−20. Crossbow adds one penetration to Bow Master. Gravity requests reload immediately. Projectile lifecycle/collision and chained visual effects are outside this pure module.

Simulation now applies the solo Sheriff's Insurance, Defender and Last Hope castle effects, independently matched by 17 original snapshots. Insurance credits before Defender's unconditional roll; Defender can cancel castle damage. Last Hope's source condition compares its threshold **below** remaining HP percentage despite the description claiming low HP; it follows a `U>0.6` roll and a random choice among all five ally slots. Successful hero rampage also consumes the two original `shake` draws before setting Fury-adjusted duration. Protection guards precede these skills, while damage absorption truncates before the minimum-one clamp. Preserve or explicitly document a later intentional correction to the Last Hope condition, rather than silently following the tooltip. Leadership changes ally aiming only; Taunt changes mission parameters; Quick Eyed changes town searching. Base aiming/teamwork are not reconstructed by this calculation module.

Dr Holliday's accuracy penalty applies to every weapon in `refreshPlayer`, although extra shells only apply to shotgun subtype 2. This source quirk is preserved. `enemy.damage` has no minimum weapon damage: armor/air rounding may yield zero. Explosion Da Bomb also multiplies damage, not only radius. The module preserves both facts.

Validation: nine focused tests cover starting Sheriff compatibility, acquired skill changes, unknown base stats, tight/range behavior, intermediate integer rounding, RNG roll boundaries, leech/status ordering, reload variants, projectile dispatch, and living weapon threshold evolution. TypeScript `--noEmit` passed when the module was added. No production build or original fixture was modified.

Independent integration evidence is recorded in `../../docs/oracle-notes.md` under actual shooting. Two Ruffle runs produced identical original traces, and production `Simulation.fireAt` matched all 22 snapshots, including every random draw and post-shot item field.
